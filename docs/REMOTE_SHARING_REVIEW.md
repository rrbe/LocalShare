## 最新产品目标

普通用户的操作应是：

```text
选择文件或分享文本 → 开启互联网分享 → 获得链接 → 发给访问者
```

- 广域网分享默认关闭，用户明确开启后才发布当前内容；App 冷启动仍需用户手动开始分享。
- App 使用内置的默认服务地址，首次启用时完成设备注册和凭据保存。
- 访问者只需浏览器，无需安装接收端 App，也无需配置网络。
- 文件按请求实时转发，Mac 必须在线，服务器保持内容不落盘的边界。
- 文件和文本都能通过广域网分享。远程权限独立于局域网权限。
- 默认服务的两段公网连接使用 HTTPS 和 WSS。
- 自托管入口保留在高级设置中，由技术用户填写地址和管理员提供的配对码。

所有内容经过中继，服务可用性和带宽由运营方承担。第一版的加密层级、远程收文本范围和具体流量额度，见后面的决策清单。

## 已复现的代码缺陷

### B1 配对过程中断开后仍重新发布

**位置：** [RemoteAgent.swift](../Sources/LocalShare/RemoteAgent.swift) 的 `connect`、`pair`、`disconnect` 和 `didOpenWithProtocol`；[AppState.swift](../Sources/LocalShare/AppState.swift) 的远程启停入口。

`connect` 创建的异步任务没有被保存或取消。它等待配对完成后直接调用 `openSocket()`，没有检查用户是否已经断开，也没有确认本次连接仍对应当前配置。WebSocket 打开后又会自动发送 `share.start`。

已复现：配对响应延迟 1.4 秒，连接开始 0.5 秒后执行断开，最终状态仍变成 `connected`，服务端实际收到 `share.start`。这会使用户已经关闭的可选远程功能重新发布内容。

完善要求：跟踪并取消连接任务，对等待后的状态更新、凭据保存和打开连接校验当前连接代次。断开、停止、忘记服务器和切换配置都需要使旧任务失效；自动重试只应在当前会话仍获准连接时执行。

- [x] 延迟配对期间断开，完成后仍保持断开，服务端没有新的 `share.start`。
- [x] 配对期间停止分享或忘记服务器，旧任务不能恢复连接或重新写入已删除的凭据。
- [x] 配对期间切换服务或重新发起连接，旧结果不能覆盖新配置、凭据或状态。
- [x] 自动停止期限到达、手动断开后，已排队的重试不能再次发布。
- [x] 临时断网后的重连仍能正常工作。

### B2 慢下载阻塞同设备其他请求

**位置：** [server/main.go](../server/main.go) 的 `shareHandler`、`agent.readLoop`、`agent.deliver` 和 `runServe`。

`deliver` 同步等待容量为 1 的请求队列，它又由所有请求共用的 WebSocket 读循环调用。HTTP handler 的 `Write/Flush` 没有写入期限；下载端停止接收数据后，写入阻塞、队列填满，其他请求的响应和控制消息也无法继续处理。handler 卡在写入内部时，无法处理现有的空闲计时器和请求取消。

已复现：真实 TCP 客户端请求大文件后不读数据，另一个请求返回 504。可控 writer 探针进一步确认，另一个请求即使已经送回完整响应仍会超时，慢请求取消后也无法退出，直到写入被解除。

完善要求：让 HTTP 写入和刷新具有有效的等待期限，并避免单个请求的应用层背压持续堵住共享读循环。缓冲、并发和清理仍需有界；超时或取消应释放对应的本机请求。

- [x] 一个浏览器暂停读取大文件时，另一个正常请求能在规定时限内返回。
- [x] 浏览器取消、读写超时后，对应本机任务和队列被清理。
- [x] 慢下载期间仍能处理停止分享、切换分享和连接关闭。
- [x] 连续、并发的慢下载不会造成持续增长的请求数、内存或 goroutine。
- [x] 正常的大文件下载不会因为总传输时间较长而被误当作空闲请求终止。

### B3 HTML 正文收完后响应偶发无法结束

**位置：** [RemoteLocalRequest.swift](../Sources/LocalShare/RemoteLocalRequest.swift) 的 `didReceive data`、`resumeAfterChunk`、完成回调，以及 [RemoteAgent.swift](../Sources/LocalShare/RemoteAgent.swift) 的 `handleLocalEvent` 和 `sendDataResponse`。

每个数据回调都会暂停本机任务，再等待 WebSocket 发送完成后恢复。对没有 `Content-Length`、通过关闭连接结束的 HTML，已观察到最后一块发送并执行恢复后仍没有请求完成回调，因此没有 `response.end`。浏览器已经收到完整正文，但会继续等待中继的 60 秒空闲超时。

已复现：真实 Release 的 16 次目录请求中出现两次正文完整但请求超时；独立约 40 KB HTML 探针也复现了相同现象。日志显示最后一块数据已发送、任务已恢复，直到浏览器取消才发生完成回调。在临时副本中移除暂停后，同场景 500 次均正常结束；这只能用于确认问题，交付实现仍需保留有界背压。上述次数是复现记录，不代表实际故障率。

完善要求：可靠协调数据发送、任务暂停恢复、正常完成和取消。已知长度和未知长度响应都应及时结束，最后一个数据块必须完整到达。

- [x] 重复请求通过关闭连接结束的 HTML，正文完整且无需等待 60 秒超时。
- [x] 同时覆盖已知长度、未知长度、空响应、最后一个数据块和中途取消。
- [x] 背压仍然有效，内存不会随整个文件大小增长。
- [x] Debug 和 Release 下均验证响应内容与完成时限。

### B4 在途请求不能越过分享边界

**位置：** [FileServer.swift](../Sources/LocalShare/FileServer.swift) 的 `handle` 和 `handleUpload`。

先取 token、稍后再取 share 的请求，可能在两次读取之间遇到分享更换。真实 TCP 回归通过较长编码路径扩大这个时间窗口，旧实现既读到了新文件，也把原已授权的上传写进了新目录。

现在在同一锁内获取 token、share、文本和权限快照，读取与上传沿用该快照。更换分享后，已经开始的请求可以完成旧内容的操作，后续旧 token 请求被拒绝；它们不能进入新分享。

- [x] 在途读取和上传保留原授权范围，不访问新文件或写入新目录。
- [x] 旧 token 后续请求返回 403，新 token 可以访问新内容。
- [x] 旧逻辑对照测试明确失败，修复后的 Debug/Release 回归通过。

### B5 中继停机后自动重连不能恢复

**位置：** [RemoteAgent.swift](../Sources/LocalShare/RemoteAgent.swift) 的 `openSocket`。

原生验收与真实 Go/Swift 链路均复现：中继停机 6 秒后重启，App 保持“自动重试”，超过 25 秒仍无新连接或分享。原先的断线测试只关闭 WebSocket、保留监听端口，没有覆盖重试遇到连接拒绝的情况。

`waitsForConnectivity = true` 使新尝试在 URLSession 内等待，未返回 App 的重试调度。现在使用默认的立即失败行为，由现有退避调度继续重试。停止、认证失败和配对取消的终止语义保留。

- [x] 监听端口关闭期间至少一次重试被拒绝，恢复后仍重新连接并发布。
- [x] 真实 Go 中继停机 6 秒，恢复约 1.7 秒后客户端重新发布。
- [x] 新回归在原逻辑下超时失败，修复后 Debug/Release 均通过；认证失败仍停止重试。

### B6 钥匙串授权等待与拒绝

**位置：** [RemoteAgent.swift](../Sources/LocalShare/RemoteAgent.swift) 的 `cachedDeviceToken`、`openSocket`；[RemoteSettings.swift](../Sources/LocalShare/RemoteSettings.swift) 的 `RemoteKeychain.value`。

临时原生 App 更新签名后，读取已有测试凭据触发系统授权窗口。进程采样确认主线程等待 `SecItemCopyMatching`，App 无法响应；原先还将所有读取错误返回为凭据缺失，默认服务可能因此注册另一台设备。

现在在后台读取凭据，等待结束后检查取消和连接代次；重连复用本次连接已经取得的凭据。只有 `errSecItemNotFound` 表示缺失，其余钥匙串错误显示为访问失败，不触发自动注册。系统授权窗口仍由 macOS 管理。

- [x] 等待凭据读取期间主线程可执行断开，迟到的读取结果不能打开连接或发布分享。
- [x] 拒绝读取显示错误，不调用默认服务的注册接口。
- [x] 同步读取对照使响应时限检查失败；修复后的 Debug/Release 回归通过。

### B7 文件分享入口不应依赖局域网地址

ContentView 的文件页只按 `hasNetwork` 判断是否显示 ShareScreen，而它只表示局域网地址或已开启的 Tailscale 地址；没有这种地址仍可能联网。原无网络页也没有互联网入口，用户无法在文件页启用中继。

现在缺少局域网地址时仍提供互联网分享卡片；已发布的远程 URL 可以直接显示文件票据。连接失败或断开后保留恢复入口，停止后的票据保留重新启动，局域网提示仅描述局域网要求。

- [x] 使用无局域网候选地址、但中继可达的原生夹具验证文件启用、二维码、下载、停止、重启和断开；下载内容逐字节一致，重启不自动发布远程分享。
- [x] 原生英文浅色与中文深色说明通过检查，局域网条件只用于局域网访问。

## 产品功能需要补齐的部分

### F1 默认服务和简单启用流程

**现状：** [RemoteSettings.swift](../Sources/LocalShare/RemoteSettings.swift) 默认地址为空；[SettingsScreen.swift](../Sources/LocalShare/SettingsScreen.swift) 要求用户填地址和配对码；Server 的 `enroll` 只接受管理员预先生成的一次性 Enrollment Key。仅提前部署服务器，普通用户仍需要逐台取得配对码。

完善方向：默认服务地址由 App 提供，首次明确开启互联网分享时，通过受限的设备注册流程取得独立凭据，并保存到 Keychain。后续复用该设备凭据。自托管保留管理员配对流程，放在高级设置中。

自动注册的准入规则需和 S2 一起确定。默认服务不能依靠写入 App 的共享永久凭据或一个通用的一次性配对码。

- [ ] 全新安装的普通用户无需填写服务地址或联系管理员即可启用默认服务。
- [x] 注册成功后再次连接复用凭据，冷启动仍需用户手动发布当前内容。
- [x] 注册失败、凭据被撤销和服务不可用时，有明确状态与恢复入口。
- [x] 忘记默认服务凭据后可以重新注册；切换到自托管后凭据不会串用。
- [ ] 服务已部署、证书有效，并用不在同一局域网的真实设备验证文件和文本分享。

### F2 广域网文本分享

**现状：** [AppState.swift](../Sources/LocalShare/AppState.swift) 的 `canEnableRemote` 要求存在文件，`applyRemotePolicy` 隐藏共享文本并关闭收文本；[TextScreen.swift](../Sources/LocalShare/TextScreen.swift) 禁止远程连接期间发送文本；[FileServer.swift](../Sources/LocalShare/FileServer.swift) 在远程模式隐藏 `/ls/text` 内容。Server 也只允许 GET/HEAD，协议没有转发请求体的能力。

第一版必须覆盖 Mac 向浏览器分享文本，以及文件和附带文本共存。文本页需要自己的远程启用入口和链接。文本更新保持同一分享会话，已有文件链接和文本链接继续有效；更换分享、停止和撤销按明确的会话边界失效。

远程收文本是否同时交付，见决策清单。若纳入，使用独立的可选开关，默认关闭；只开放所需的文本端点和请求体，沿用已有文本校验与接收限制，通过本机 FileServer 处理。不能通过开放所有 POST 请求来顺带暴露文件写入能力。

- [x] 纯文本分享可以直接启用远程访问，浏览器能够查看和复制。
- [x] 文件与文本共存时，两种内容及其导航都正确。
- [x] 更新文本不作废同一会话的链接；需检查 `pushToServer` 无条件重新 `share.start` 导致远程 token 变化的路径。
- [x] 停止、清除或更换分享后，旧远程链接不能访问新内容。
- [x] 若交付远程收文本，开关、大小限制、取消、鉴权和关闭后的拒绝行为均有效。
- [x] 中文、换行、特殊字符、网页转义和浏览器语言选择保持正确。

### F3 局域网和远程权限独立

**现状：** [AppState.swift](../Sources/LocalShare/AppState.swift) 的 `effectivePermission` 和 `applyRemotePolicy` 会改动整个 FileServer；开启远程访问后，局域网上传和文本传递也被暂停。这是现有方案的行为，本轮需要调整。

完善方向：局域网继续遵循用户原有设置；远程文件访问采用自己的只读边界，远程文本采用自己的发送和可选接收规则。远程请求的权限应在可信转发边界生效，同时复用 FileServer 的路径、鉴权和内容处理逻辑。

- [x] 开启和关闭互联网分享都不会修改局域网权限偏好。
- [x] 局域网上传、发文本和收文本按原设置继续工作。
- [x] 远程文件写入仍被拒绝；文本接收只按远程开关放行。
- [x] 文件与文本页、设置及网页表单和权限说明反映实际访问范围；目录和 Markdown/JSON/CSV 预览的中英文范围标识均通过检查。
- [x] 本机 token、远程分享代次和权限不能由浏览器提供的身份头绕过。

## 默认公网服务的上线条件

### S1 公网连接和生产文档使用 TLS

**现状：** RemoteSettings 接受 HTTP，RemoteAgent 可建立 WS，Server 可启动公网 HTTP。[部署文档](../website/server/deployment.md) 虽有 HTTPS 示例，systemd 的 `ExecStart` 和健康检查仍使用公网 HTTP。

默认服务应对浏览器提供 HTTPS，对 App 提供 WSS；公网配对和注册同样使用 HTTPS。证书校验保持有效，公网地址不应静默降级为明文连接。开发测试所需的本机 HTTP 应有清楚的使用边界。

- [ ] 默认服务地址、注册、配对、WebSocket 和生成的分享链接全部使用 TLS。
- [x] 公网明文地址、证书错误和不安全重定向有明确的拒绝行为。
- [x] 安装命令、systemd、健康检查和完整验证命令使用同一套生产配置。

### S3 在线设备撤销的语义

**现状：** `stateStore.revokeDevice` 修改持久化标记，`agentHandler` 仅在建立 WebSocket 时检查。已经在线的设备和已有 Share Token 不会因此立即失效。原方案只承诺阻止新连接，当前行为符合该限定。

### 手动部署工作与 CDN 的区别

CDN 是可选的部署层。当前 qcloud 候选使用独立子域名直接访问 Nginx，由 Nginx 终止 HTTPS/WSS，再转发到回环中继；使用这一方式无需配置 CDN。2026-10-12 再次查询，`share.fairydog.net` 仍指向 EdgeOne CNAME。若保留 EdgeOne，则需额外完成下面第三列，现有候选没有包含 EdgeOne 专用配置或验收。

| 工作 | 直接访问 qcloud 的候选方案 | 保留 EdgeOne 需要额外处理 |
| --- | --- | --- |
| 域名与 DNS | 使用 `share.fairydog.net`，A 指向 `81.71.95.2`；清理冲突的同名记录 | 保留 EdgeOne CNAME，源站填 qcloud IP，避免将加速域名作为自身源站 |
| 证书与加密 | Nginx 安装覆盖该子域名的有效证书，公网使用 HTTPS/WSS | EdgeOne 边缘证书也要覆盖该子域名；回源使用 HTTPS，并验证源站证书及 Host/SNI 匹配 |
| 程序与状态 | 校验并安装 Linux 二进制；专用用户运行，保留 `/var/lib/localshare/state.json` | 中继本身安装方式相同 |
| 服务配置 | systemd 监听 `127.0.0.1:18080`，设置 HTTPS public-url 和 `--behind-proxy`；Client/Server 一起升级到 v2 | public-url 仍使用访问者所用的公开域名，不写 CDN 节点或源站 IP |
| WebSocket | Nginx 支持 HTTP/1.1 Upgrade，代理读写空闲时限设为 65 秒 | 为该域名启用 WebSocket，透传认证头；空闲时限覆盖 15 秒心跳并留余量，例如 120 秒，实测断线恢复 |
| 文件流与缓存 | 关闭代理缓冲，分享响应不缓存 | 对整个中继子域名绕过缓存，包括文件、文本、API、错误响应和 healthz；关闭离线缓存，验证撤销后不会继续返回旧内容 |
| 请求转发 | 保留路径、查询参数、Range、Content-Type 和所需请求方法 | 检查边缘规则没有改写分享路径、丢失 raw/path 参数、拦截文本 POST 或注册请求 |
| 来源 IP 与限流 | Nginx 用 TCP 来源覆盖 X-Real-IP，Server 仅信任回环代理 | 只信任 EdgeOne 回源网段，使用其可信来源头恢复访客 IP，再交给 Server；不能直接信任任何来访者携带的头，否则来源可伪造；配置错误会将访客统计与注册限流合并到 CDN 节点 |
| 网络与安全规则 | 确认安全组允许 HTTPS；中继端口仅回环，80 端口按 ACME 验证方式需要开放 | 检查源站回源准入、WAF 和 Bot 规则，确保合法 API/WSS 不被交互式挑战阻断 |
| 容量与费用 | 按服务器实际带宽确定设备/整体限速、并发和注册额度，设置账单告警 | 再核对 CDN 请求、流量和长连接的计费及套餐限制；不缓存意味着文件仍需回源 |
| 续期、日志与回滚 | 续期后校验并 reload Nginx；避免记录分享 token；备份 binary/unit，保留状态文件 | 边缘与源站证书都要续期；CDN 日志同样避免暴露分享 token，回滚时同步检查边缘配置 |
| 真实网络验收 | 用不同网络的 Mac 与浏览器验证注册/配对、文件、文本、Range、停止、撤销及重连 | 在经过 CDN 的完整链路上重复验收，并检查慢下载、大文件和缓存绕过 |

EdgeOne 的 [源站与 Host 配置](https://edgeone.ai/document/54208)、[WebSocket 配置](https://edgeone.ai/document/46971) 和 [默认回源来源头](https://edgeone.ai/zh/document/54211) 分别说明以上额外配置。候选中的 `X-Real-IP $remote_addr` 适用于直接访问；经过 CDN 时必须先完成可信来源还原。第一版为可信中继；经过 CDN 时 CDN 也处于内容可读取的信任范围，HTTPS/WSS 仍不提供端到端加密。
