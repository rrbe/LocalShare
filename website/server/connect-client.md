# 连接 Client

发送端运行 LocalShare，接收端打开浏览器。选择默认公共服务，或在设置中换成自己的 Server。

## 使用默认服务

1. 在 LocalShare 中选择文件、文件夹或要分享的文本。
2. 在分享页的远程访问区域点击「连接」。App 会自动注册并连接默认服务。
3. 将生成的远程链接或二维码发给接收者。

<div class="flow">准备分享  ──▶  连接  ──▶  发送链接  ──▶  对方浏览器打开</div>

默认服务的可用性取决于公共中继是否在线。若之前设置了自托管，在「设置 → 网络」点击「使用默认服务」即可切回。

## 使用自托管服务器

### 1. 首次配对

先完成 [Server 部署](./deployment)，确认公开地址的 `/healthz` 返回 200，再在服务器上生成一次性配对码：

```bash
sudo -u localshare /usr/local/bin/localshare-server key create --name macbook
```

在 App 的「设置 → 网络 → 使用自托管服务器」中填写：

| 字段 | 内容 |
| --- | --- |
| 服务器地址 | HTTPS 基地址，如 `https://203.0.113.10` 或 `https://share.example.com`；自定义端口需一起填写 |
| 配对码 | 上面命令生成的一次性 Enrollment Key |

地址不带额外路径或查询参数。点击「配对」即可保存设备凭据；也可点击「保存」，在分享页首次连接时完成配对。

配对码只使用一次，App 将后续连接所需的设备凭据保存在 macOS 钥匙串中。接收者无需配对码。

### 2. 发布分享

回到文件或文本页，准备好分享内容后点击「连接」。显示远程地址后，将链接发给接收者。后续使用同一服务器时无需再次输入配对码。

## 分享期间

Mac 和 LocalShare 需要保持运行并联网。远程文件只读；接收文本需单独开启「允许通过互联网收文本」，局域网权限保持原设置。

- 点击「断开」，当前远程链接立即失效，保留设备配对。
- 更换分享内容或 Server 重启后，需要使用新链接。
- App 冷启动不会自动公开内容；准备好分享后再点击「连接」。
- 自托管设置中的「忘记服务器」会删除设备凭据，下次需新的配对码。

分享内容实时经过中继，中继可读取内容，不保存文件。将远程链接发给需要访问的人即可。

::: details 连接失败时检查什么
| 现象 | 检查 |
| --- | --- |
| 无法连接服务器 | 从另一网络访问 `<服务器地址>/healthz`，确认 HTTPS 证书有效、入口可达 |
| 配对失败 | 配对码是否已使用；用 `key create` 生成新码 |
| 「连接」不可用 | 是否已选择文件、发送文本或开启远程收文本 |
| 健康检查通过，App 仍无法上线 | 检查代理与 CDN 是否支持 WebSocket，是否拦截 App 请求 |
| 分享链接无法打开 | 是否已断开、更换内容或重启 Server；重新发送当前链接 |

自托管还可运行 `device list` 查看配对记录，使用 `journalctl -u localshare-server` 查看服务日志。
:::
